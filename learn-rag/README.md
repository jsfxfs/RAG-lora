## 🧭 这个项目是什么

**一句话**：给 50 份上市公司年报 PDF 建一个能"开卷考试"的问答系统——用户问
"威力传动 2025 年归母净利润是多少"，系统从 4000+ 个文本块里找到正确的那几块，
交给大模型读出答案 **-93,767,876.98 元**，并标注来源。

**核心文件地图**（项目根目录 `RAG-lora/`）：

```
RAG-lora/
├── 01_年报PDF/           # ① 原始素材：50 份年报 PDF
├── 02_文本抽取/           # ② 清洗文本 + 结构化表格 + 切块
├── 03_LoRA数据/           # ③ 微调训练数据（A 侧 10 家公司）
├── 04_RAG数据/            # ④ RAG 索引语料（A 侧）
├── heldout_B/             # 评测集 B：15 家"未见"公司（考卷）
├── rag/                   # 检索核心模块
│   ├── retrieve.py        #   向量/BM25 混合召回 + 公司路由
│   ├── rerank.py          #   bge-reranker 精排
│   ├── build_index.py     #   建 FAISS 索引
│   └── llm.py             #   生成后端封装（API / 本地）
├── rag_chat.py            # 问答入口（命令行交互）
├── eval_retrieval.py      # 主评测脚本（4 配置消融）
├── eval_validity/         # 评测效度加固（recall/拒答/口语化/裁判校准）
└── eval_local/            # 本地模型评测结果
```

**技术栈速览**：

| 环节 | 选型 |
|---|---|
| PDF 解析 | pypdf + pdfplumber（表格） |
| 向量模型 | BAAI/bge（本地，CPU/GPU 均可） |
| 关键词检索 | BM25（rank_bm25 + jieba 分词） |
| 融合 | RRF（倒数排名融合） |
| 精排 | bge-reranker-large（交叉编码器） |
| 向量库 | FAISS |
| 生成 | DeepSeek-V4-Flash（API）/ Qwen3-4B ± LoRA（本地） |
| 评测 | LLM-as-Judge + evidence + recall@k |

## 💡 三条最值得记住的经验

如果只带走三句话，请带走这三句（详细论证见对应章节）：

1. **RAG 的瓶颈在检索，不在生成。** 检索拉满后，4B 本地小模型能达到商用 API 96% 的
   水平；反过来，检索不行时换再强的生成模型也救不回来。（→ 03、04 章）

2. **LoRA 和 RAG 不是竞争关系，是分工关系。** LoRA 是"闭卷背书"（把知识写进参数），
   RAG 是"开卷考试"（把知识放在上下文）。开卷场景下 LoRA 没有增益——这是花真金白银
   跑出来的负结果，比正结果更值钱。（→ 04 章）

3. **先测量，再决策，不迷信技术名词。** HyDE？先做口语化测试，结论是不需要。
   GraphRAG？先算查询模式，结论是不适配。每一个"没做"背后都有数据支撑——
   "测过所以没做"远比"听说很火所以做了"有说服力。（→ 05、07 章）
