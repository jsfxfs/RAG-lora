# 02 · 数据篇：从 PDF 到语料

> **难度**：⭐⭐
> **学完你能回答**：年报 PDF 怎么变成能检索的干净文本？为什么"按章节切块"比固定长度好？
> 表格怎么处理？训练数据里的"检索语境残留"是什么坑？

---

## 1. 为什么数据是 RAG 的第一性原理

RAG 系统里最不性感、但决定上限的环节就是数据。项目后期做错题归因时发现：
**检索增强做满后，剩余错误的大头是"表格线性化质量"——数据侧问题，不是模型问题。**

这条流水线一共 4 步：

```
① 下载              ② 抽取+清洗+结构化           ③ LoRA 数据          ④ RAG 数据
巨潮API ──▶ 50份PDF ──▶ 纯文本 + 表格(Markdown) ──▶ qa_alpaca.json ──▶ rag_chunks.json
                        │                          (喂 LLaMA-Factory)   (建 FAISS 索引)
                        └── 按章节切块
```

对应脚本：`download_cninfo_reports.py` → `clean_report.py` → `generate_qa.py` / `gen_heldout.py`

---

## 2. 第一步：批量下载年报（`download_cninfo_reports.py`）

从巨潮资讯网（cninfo，上市公司法定信息披露平台）API 批量下载 50 份中文年报全文。
看似简单的爬虫，踩了 5 个坑：

| # | 坑                     | 解法                                   |
| - | ---------------------- | -------------------------------------- |
| 1 | 接口单页最多返回 30 条 | 翻页累计                               |
| 2 | 时间戳是毫秒           | `ts_to_date()` 转成日期              |
| 3 | 返回的不是 PDF 真地址  | 要手动拼`static.cninfo.com.cn/` 前缀 |
| 4 | 同一公司可能有多条公告 | 按`secCode` 去重，每家只留 1 条      |
| 5 | 混着"摘要版"和"英文版" | 按标题过滤，只留中文年报**全文** |

> 💡 **通用经验**：对接任何开放 API，先手动调一次看真实返回结构，别信文档。

## 3. 第二步：清洗与结构化（`clean_report.py`）—— 全项目最多返工的地方

### 3.1 为什么 PDF 抽出来的文本不能直接用

pypdf 直接抽出来的年报文本长这样（示意）：

```
中简科技股份有限公司 2025 年年度报告        ← 每页都重复的页眉
第 23 页 共 187 页                        ← 页码行
公司主要从事高性能碳纤维及织物、碳纤维预浸
料的研发、生产、销售...                    ← 正文被硬换行切断
...............................目录 12    ← 目录页的点线
```

页眉页脚会**污染每一个 chunk**（检索时"2025 年年度报告"这种词和所有块都相似），
断裂的行会破坏语义。清洗分 6 步：

```
extract_pages(pdf)        按页抽文本（保留页边界——跨页对比才能识别页眉页脚）
      │
clean_pages(pages)        ① NFKC 归一化 + 删页码行
      │                   ② 跨页检测重复行 → 判定为页眉页脚删除
      │                   ③ 修复行断裂（把被硬换行切断的句子接回去）
      │                   ④ 清理目录页、模板套话
      ▼
extract_tables(pdf)       ⑤ pdfplumber 抽线框表 → 转 Markdown 表格
      │
reorder_sections + dedup  ⑥ 按"第X节"重排章节顺序 + 去重
      ▼
build_chunks(text, tables) 章节切块 + 表格块插入
```

### 3.2 切块策略：按章节切，不是固定窗口

**反面教材（项目真实历史）**：第一版代码是固定 1000 字滑动窗口——一个 chunk 可能
前半段是"管理层讨论"、后半段是"股东信息"，语义被拦腰斩断，检索命中了也答不对。

**正确做法**：识别年报的章节标题（"第三节 管理层讨论与分析"等）按章节切，
每块是**语义完整的章节片段**；超长章节内部再用滑动窗口兜底。

```
固定窗口切块                       按章节切块
┌──────────────┐                 ┌──────────────────┐
│…讨论与分析末尾  │                 │ 第三节 管理层讨论与 │
│第四节 公司治理  │ ← 语义断裂       │ 分析（完整章节）    │ ← 语义完整
│公司治理开头…   │                 └──────────────────┘
└──────────────┘                 ┌──────────────────┐
                                 │ 第四节 公司治理     │
                                 └──────────────────┘
```

> 📌 **诚实记录**：这个"说好按章节切、实际写成滑动窗口"的问题是用户 review 时
> 发现的。教训：**验收代码要看实现，不能只听描述。**

### 3.3 两个差点毁掉数据的 bug

**Bug 1：数字过滤把财务报表全丢了。**
早期为防幻觉加了一条规则："数字占比 ≥35% 的段落整段丢弃"。听起来合理——纯数字块
让 LLM 生成 QA 容易出幻觉。但**利润表、资产负债表恰恰全是数字**，这条规则把最有
价值的财务数据全干掉了。
**修复**：把"造 QA"和"进索引"两条链路分开对待——切块层移除该过滤（所有块都进
RAG 索引），只在"生成 QA"这一环跳过**结构化失败的裸数字碎块**（不用它出题）。
注意：结构化成功的真财报表格块（`is_table=True`，带表头/行名）**照常出题**，
pilot 里 37 个表格块全部参与了 QA 生成。

> ❓ **常见误解："不出题，那真实用户问到这些数字怎么办？"**
> 不影响。"出题"和"答题"是两条完全不同的链路：
>
> ```
> 纯数字块 ──▶ 链路①：生成 QA（离线造训练/评测数据）  ❌ 跳过
>          └─▶ 链路②：进 RAG 索引（在线真实问答）    ✅ 保留
> ```
>
> 跳过链路①只是不让 LLM 拿一段没有上下文的数字矩阵出题（极易造出答案对不上
> 行列的幻觉题，污染训练数据）。真实提问时走的是链路②：块在索引里、能被检索到，
> 原文进 prompt，模型照常读出答案——RAG 是开卷考试，**块不需要"被出过题"才能
> 用来答题**。代价只有一个：这类块没进考卷，评测分数覆盖不到"针对裸数字块提问"
> 的场景（如实记录）。

**Bug 2：pdfplumber 把正文误判成表格。**
单份年报 pdfplumber 抽出 ~260 张"表"，人工一看 86% 是**双栏排版的正文**被误判。
**修复**：加标题白名单过滤——只保留标题命中"资产负债表/利润表/现金流量表/
主要会计数据"等关键词（STMT_KW）的真实财报表格。实测 263 → 37 张，全是真表。

> 💡 **通用经验**：工具的输出永远要抽样人工看。"抽到 260 张表"听起来是好消息，
> 打开一看才知道是灾难。

## 4. 第三步：造 QA 数据（`generate_qa.py` / `gen_heldout.py`）

### 4.1 基本流程

对每个 chunk，调 DeepSeek API 生成若干问答对：

```
chunk（~1000字章节片段）
   │
   ▼  prompt："基于以下年报片段生成N个问答对，答案必须来自片段，不得编造"
DeepSeek-V4-Flash
   │
   ▼
[{"instruction": "中简科技的主营业务是什么？",
  "output": "公司主要从事高性能碳纤维..."}]
   │
   ├──▶ qa_alpaca.json    （alpaca 格式，喂 LLaMA-Factory 微调）
   └──▶ qa_sharegpt.json  （sharegpt 格式，同内容异格式）
```

A 侧 10 家产出 7078 条训练 QA；B 侧 15 家产出 3108 条评测 QA。

### 4.2 坑：训练数据里的"检索语境残留"

生成的 QA 中约 **19%** 的答案带这样的开头：

> "**根据财报片段**，公司 2025 年营业收入为..."

问题在哪？这些 QA 要拿去做**闭卷**微调——训练后模型回答任何问题都会凭空说
"根据片段"，可它面前根本没有片段，等于**学会了假装引用**。

**修复（`clean_qa.py`）**：全局正则删除"根据(报告原文|财报片段|年报片段|...)，"
短语（句首句中都清），保留真实答案。1351 条受影响 → 清后残留 23 条
（均为合法的自然回指，如"该报表缺少片段原文"）。同时**保留**"根据企业会计准则/
《公司法》"等合法用法——正则只匹配"根据 + 文档指代词"。

> 💡 **通用经验**：LLM 生成的训练数据必带生成时的语境印记，喂给下游前要按
> 下游的使用场景（闭卷 vs 开卷）清洗。

### 4.3 大坑：评测 QA 没存"归属"字段（后来整批重造）

第一版 `gen_heldout.py` 生成的评测 QA 只有 `instruction` / `output` 两个字段——
**没记录这条 QA 来自哪家公司**。后果在评测阶段全面爆发：

```
问题："公司的盈利模式是什么？"        ← 15 家共库，"公司"是哪家？！
  │
  ▼
检索：无从定位目标公司 → 随机命中某一家
  ▼
裁判：答的是 A 家、参考答案是 B 家 → 判 0 分
  ▼
所有配置的绝对分都被压低（vec 基线仅 49%，失真）
```

**两条修复路线的权衡**（真实决策过程）：

| 方案              | 做法                                                                   | 成本                                  | 最终选择    |
| ----------------- | ---------------------------------------------------------------------- | ------------------------------------- | ----------- |
| 一：重造 QA       | 改脚本（问题强制带公司名 + 落盘`source`/`company` 字段）重跑 15 家 | ~4500 次 API 调用，旧评测数字全部作废 | ✅ 选了这个 |
| 二：BM25 反推归属 | 用参考答案反查 4461 块推断归属                                         | 零成本但归属准确率存疑                | ❌          |

重造后：3108 条 QA，`source`/`company` 覆盖 100%，问题带公司名 99.9%。
这次修复**解锁了后面所有关键实验**：公司路由评测、recall@k 直算、per-company 分析。

> 📌 **最重要的数据教训**：**元数据（来源、归属、时间）在生成时是免费的，
> 事后补要付十倍代价。** 造任何数据集时，能带的溯源字段全都带上。

## 5. 工程细节：断点续存

QA 生成要调几千次 API，中途崩溃很常见。项目的方案：

- `--limit N` 显式控制只跑前 N 份（配合共享 API 额度管理）；
- 每跑完一份 PDF 立即落盘，重跑时按 `source` 跳过已完成的；
- `--fresh` 强制从头重跑（改了切块参数时必须用，否则旧产物被当作"已完成"跳过）。

**一个隐蔽风险**（如实记录）：第一版以"chunks 文件是否存在"判断完成度——若某家
切块成功但 QA 生成中途崩溃，重跑会整家跳过，造成"有 chunk 无 QA"被**静默丢弃**。
重造版改用独立的 `qa_done.json` 进度表，与 chunks 解耦。

> 💡 **通用经验**：断点续存的"完成标志"必须精确对应"全部产物就绪"，
> 用中间产物当标志会静默丢数据。

## 6. 本章小结

| 教训             | 一句话                                                      |
| ---------------- | ----------------------------------------------------------- |
| 切块             | 按语义结构（章节）切，不要无脑固定窗口                      |
| 清洗             | 页眉页脚靠跨页对比识别；工具输出必须抽样人工验              |
| 过滤规则         | "防幻觉"规则可能误杀最有价值的数据（财务报表事件）          |
| 训练数据         | LLM 生成的数据带语境残留，按下游场景清洗                    |
| **元数据** | **生成时免费，事后补十倍代价——source 字段永远要带** |
| 断点续存         | 完成标志要对应全部产物，否则静默丢数据                      |
