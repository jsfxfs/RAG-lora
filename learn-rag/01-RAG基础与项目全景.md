# 01 · RAG 基础与项目全景

> **难度**：⭐ 入门
> **学完你能回答**：RAG 为什么存在？它和微调有什么区别？这个项目的完整链路长什么样？

---

## 1. 从一个问题说起

假设你问大模型：

> "威力传动 2025 年归属于上市公司股东的净利润是多少？"

直接问 ChatGPT / DeepSeek，会遇到三个致命问题：

| 问题 | 原因 |
|---|---|
| ❌ **不知道** | 模型训练截止日期之后的年报，它根本没见过 |
| ❌ **胡编**（幻觉） | 不知道也硬答，编一个看起来很像的数字——金融场景致命 |
| ❌ **无法溯源** | 就算答对了，你也不知道依据是什么，没法核实 |

解决思路有两条路：

```
路线 A：微调（LoRA）              路线 B：RAG（检索增强生成）
"把年报背下来"                    "考试时允许翻书"

  年报 ──▶ 造问答对 ──▶ 训练        年报 ──▶ 切块建索引
             │                              │
             ▼                              ▼
      知识写进模型参数              提问时先检索相关段落
             │                              │
             ▼                              ▼
        闭卷考试                   段落+问题一起喂给模型 = 开卷考试
```

**本项目两条路都走了**，还让它们同台打了一架（结果见 04 章，很有意思：
LoRA 闭卷很强，但在开卷场景下增益为零）。

---

## 2. RAG 的最小工作原理

RAG = **R**etrieval-**A**ugmented **G**eneration（检索增强生成）。
把它想成一个"开卷考试"的流程：

```
                ┌──────────────────────────────────────────┐
                │              离线阶段（备考）               │
                │                                          │
   50 份年报 PDF ──▶ 抽取清洗 ──▶ 切成 ~1000 字的块 ──▶ 向量化 │
                │                    (chunk)        (embedding)
                │                                     │     │
                │                                     ▼     │
                │                               FAISS 索引库 │
                └──────────────────────────────────────────┘

                ┌──────────────────────────────────────────┐
                │              在线阶段（考试）               │
                │                                          │
  用户提问 ──▶ 向量化 ──▶ 在索引库里找最相似的 top-6 块         │
                │                    │                     │
                │                    ▼                     │
                │    "请基于以下片段回答问题：【片段1】…【片段6】 │
                │     问题：威力传动2025年归母净利润是多少？"    │
                │                    │                     │
                │                    ▼                     │
                │               大模型生成答案                │
                │        "-93,767,876.98 元 [来源: 片段2]"   │
                └──────────────────────────────────────────┘
```

三个关键词先混个脸熟，后面章节会反复出现：

- **chunk（块）**：把长文档切成的小段。本项目按**年报章节**切（不是无脑固定长度），
  50 份年报共切出 4000+ 块；
- **embedding（向量）**：把一段文字变成一串数字（向量），语义相近的文字向量也相近。
  本项目用 BAAI 的 bge 模型；
- **top-k 检索**：从几千个块里找出和问题最相似的 k 个（本项目 k=6）。

## 3. RAG vs 微调：什么时候用哪个？

这是面试高频题，本项目用真实实验给出了答案（详见 04 章）：

| 维度 | LoRA 微调（闭卷） | RAG（开卷） |
|---|---|---|
| 知识存哪 | 模型参数里 | 外部索引库里 |
| 新增一份年报 | 重新训练 | 建索引追加，几分钟 |
| 回答没见过的公司 | ❌ 零样本，只能靠猜 | ✅ 只要块在库里就能答 |
| 数字精确性 | ❌ 容易背串、过期 | ✅ 原文就在上下文里 |
| 可溯源 | ❌ | ✅ 能标注来源片段 |
| 擅长的事 | 答题**风格**、领域语气 | 事实**准确性**、时效性 |

**项目结论**：金融年报这种"事实密集 + 频繁更新 + 必须可溯源"的场景，RAG 是主力，
LoRA 只贡献了"答案简洁不啰嗦"的风格价值（微调后答案中位长度 73 字符 vs 原始 206 字符）。

## 4. 本项目全景图

### 4.1 数据怎么组织：A/B 两侧隔离

项目最重要的实验设计之一：把 50 份年报分成**互不相交**的两组。

```
50 份年报 PDF
 ├── A 侧（10 家）──▶ 造 QA ──▶ 训练 LoRA        「模型背过的书」
 │                └──▶ rag_chunks ──▶ indexA
 │
 └── B 侧（15 家）──▶ 切块 ──▶ B 侧索引（KB）      「模型没见过的书」
                  └──▶ 3108 条评测 QA（考卷）
 （其余 25 家未处理，属可选扩展）
```

**为什么这么设计？** 为了公平回答"LoRA vs RAG 谁强"：
- LoRA 训练只见过 A 侧 → 对 B 侧公司是**零样本**（没背过）；
- RAG 的知识库只放 B 侧 → 考 B 侧问题时是**开卷**；
- 同一份 B 侧考卷考两者 → 差距就是"背书 vs 翻书"的差距。

> 💡 这叫 **held-out（留出）评测集**。如果考卷题目模型训练时见过，
> 分数就是虚高的——这个原则贯穿全项目（05 章还会讲"考卷近亲繁殖"问题）。

### 4.2 系统完整链路

```
问题："股票代码300904的公司2025年归母净利润是多少？"
  │
  ▼
【公司路由】 正则识别"300904" → 锁定威力传动 → 只在它的 247 块里搜
  │
  ▼
【混合召回】 向量检索（语义相似）+ BM25（关键词匹配）各取 20 候选
  │          └── RRF 倒数排名融合合并
  ▼
【精排】     bge-reranker 对 20 个候选逐一精细打分 → 取 top-6
  │
  ▼
【生成】     top-6 片段 + 问题 → DeepSeek API（或本地 Qwen3-4B）
  │
  ▼
答案："-93,767,876.98 元 [来源: 片段2]"
```

四个检索组件不是一次到位的，是**一级一级加上去、每级都用 100 题实测涨分**才保留的：

```
acc  50% ────▶ 67% ────▶ 77% ────▶ 85%
     纯向量    +BM25混合   +精排      +公司路由
              (+17pp)    (+10pp)    (+8pp)
```

这条"消融曲线"是整个项目最核心的成果，03 章逐级拆解。

四个档位在后续文档的表格里有固定的**配置名**，先认个脸（它们是累积叠加的，
每一档都包含前一档的全部组件）：

```
vec       = 纯向量                                        → acc 50%
hybrid    = 向量 + BM25/RRF（加混合召回）                  → acc 67%
hr        = 向量 + BM25/RRF + 精排（加 reranker，故名 h+r） → acc 77%
hr_route  = 向量 + BM25/RRF + 精排 + 公司路由               → acc 85%
```

### 4.3 动手试试

项目环境下（`RAG-lora/` 目录，llf 环境 Python）：

```bash
# 最简单：向量检索 + API 生成（公司路由默认开启，会打印 [路由] 威力传动；
# 加 --no-route 可关闭，体验无路由的裸检索）
python rag_chat.py -q "威力传动2025年归母净利润是多少？"

# 全增强：混合召回 + 精排 + 显示命中的片段
python rag_chat.py --hybrid --rerank --show-hits -q "股票代码300904的公司净利润？"
```

`--show-hits` 会打印每个命中块的双路排名（向量第几、BM25 第几）和精排分数——
**可解释性**是这套检索设计的加分项。

## 5. 本章小结

| 概念 | 一句话 |
|---|---|
| RAG | 开卷考试：先检索相关段落，再让模型基于段落作答 |
| 微调 | 闭卷考试：把知识训练进模型参数 |
| chunk | 文档切出来的小段，检索的最小单位 |
| held-out 评测集 | 模型/索引都没见过的"新考卷"，防止分数虚高 |
| 消融实验 | 一次只加一个组件，量化每个组件的独立贡献 |
